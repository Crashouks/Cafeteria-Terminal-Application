# ЛР1. Кав'ярня — приймання та облік замовлень

Консольний Java-застосунок кав'ярні, що поєднує дві частини:

1. **Приймання замовлень** — введення характеристик двох замовлень за зміну
   та розрахунок вартості кожного (чек).
2. **Облік замовлень** — агрегована статистика по зміні: кількість
   замовлень, загальна виручка, середній чек, найбільший чек і порівняння
   фактичної виручки з планом.

## Предметна область і сутності

**Сутність 1: "Замовлення" (`Order`)** — одна позиція замовлення клієнта.
Характеристики, що вводяться з консолі (для кожного з двох замовлень):

| Характеристика         | Тип      | Приклад       |
|-------------------------|----------|---------------|
| Ім'я клієнта             | `String` | `Олена Ковальчук` |
| Назва напою              | `String` | `Капучино`    |
| Об'єм порції, мл         | `int`    | `350`         |
| Ціна за одну порцію, грн | `double` | `65.5`        |
| Кількість порцій         | `int`    | `3`           |
| Знижка клієнта, %        | `double` | `10`          |

**Сутність 2: "Облік зміни" (`ShiftAccounting`)** — зведені показники,
що обчислюються на основі всіх прийнятих замовлень:

| Характеристика          | Тип      | Приклад     |
|--------------------------|----------|-------------|
| Дата зміни                | `String` | `10.09.2026`|
| Плановий обсяг виручки    | `double` | `300`       |
| Кількість замовлень       | `int`    | `2`         |
| Загальна виручка          | `double` | обчислюється |
| Середній чек              | `double` | обчислюється |

## Логіка обробки (розгалуження `if...else`)

Для кожного замовлення:
1. **Розмір порції** визначається за об'ємом:
   - `>= 400` мл — Великий (L)
   - `>= 300` мл — Середній (M)
   - інакше — Малий (S)
2. **Бонус лояльності**: якщо кількість порцій `>= 3`, додається +5% до знижки.
3. **Розрахунок вартості чека**:
   - `subtotal = ціна_за_порцію × кількість`
   - `знижка_сума = subtotal × (знижка_клієнта + бонус) / 100`
   - `до_сплати = subtotal − знижка_сума`

Для обліку зміни (після обох замовлень):
4. **Загальна виручка** = сума чеків обох замовлень; **середній чек**
   = виручка / кількість замовлень.
5. **Найбільший чек зміни**: порівнюються `total1` і `total2`, визначається
   чек-лідер і клієнт, що його зробив.
6. **Виконання плану**: якщо фактична виручка ≥ планової — статус
   `ВИКОНАНО`, інакше — `НЕ ВИКОНАНО`.

Усі результати (чеки й облік зміни) виводяться через `System.out.printf`
з двома знаками після коми для дробових значень (`%.2f`).

## Вимоги

- Java 17+ (сумісно з Java 21). `javac` не обов'язковий — можна
  запускати `.java`-файл напряму (single-file source execution).

## Запуск

### Варіант 1 — без компіляції (Java 11+)
```bash
java Main.java
```

### Варіант 2 — класичний спосіб
```bash
javac Main.java
java Main
```

> Якщо консоль виводить кракозябри замість кирилиці (типово для
> Windows-термінала), запускайте з явним UTF-8:
> ```bash
> java -Dstdout.encoding=UTF-8 -Dstdin.encoding=UTF-8 Main.java
> ```

## Git-flow

```bash
# 1. Створити гілку лабораторної роботи
git checkout -b lr1/cafe-order-console

# 2. Додати файли
git add Main.java README.md
git commit -m "LR1: приймання та облік замовлень кав'ярні"

# 3. Запушити гілку
git push -u origin lr1/cafe-order-console

# 4. Створити Pull Request у main (через веб-інтерфейс GitHub
#    або, якщо встановлено GitHub CLI):
gh pr create --base main --head lr1/cafe-order-console \
  --title "LR1: Кав'ярня — приймання та облік замовлень" \
  --body "Реалізовано консольне введення характеристик замовлення, розрахунок вартості зі знижками, форматований вивід чека."
```

Не забудьте, що дедлайн — **2 тижні від дати першої пари** цієї
лабораторної, а PR потрібно відкрити до цього терміну.
